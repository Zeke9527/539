# 539 數據研究室｜v7.8.1（雙模式・TOP 15・固定選2碼・載入修正）

GitHub Pages 靜態網站。提供兩種由歷史回測選出的固定預測模式，使用者可在介面中切換：

- **模式一：歷史訓練35期、排除D1～D3、選2碼。**
- **模式二：歷史訓練49期、排除D1～D4、選2碼。**

兩種模式共用相同評分模型、TOP 15候選池及先驗強度10。預設為模式一。介面列出最近15期開獎資料，選定其中一期作為起始期D0；系統依所選模式確認是否已有足夠的後續排除期及D0以前訓練資料。

## 演算流程
1. 自動抓取最近200期官方歷史資料，供最近15期清單、起始期選擇及模型訓練使用。
2. 使用者選擇模式一或模式二。
3. 選定D0後，僅使用D0以前最近35期（模式一）或49期（模式二）歷史資料進行後五期轉移計分。
4. 對D0五個號碼分別計算其在歷史出現後，未來五期內每個號碼至少出現一次的比例；五個觸發號碼等權平均，先驗強度固定10。
5. 取分數最高前15碼，平手時號碼小者優先。
6. 模式一排除D1、D2、D3；模式二排除D1、D2、D3、D4。D0不排除。
7. 保留原始排名順序，輸出排除後前2碼；若不足2碼，如實顯示實際剩餘數量，不補入已排除號碼。
8. 若排除後下一期（模式一D4、模式二D5）已開獎，畫面會顯示歷史回放命中；否則以預測模式顯示。

## 起始期可用條件
模式一必須已有完整後續3期資料，且D0以前至少有35期歷史資料。模式二必須已有完整後續4期資料，且D0以前至少有49期歷史資料。當後續指定排除期數已齊、目標期尚未開出時，產生預測；目標期已開出時則作歷史回放。

## GitHub Pages 部署
將本資料夾內所有檔案上傳到 GitHub repository 根目錄，於 Settings → Pages 選擇 Deploy from a branch、main、/(root)。網站不需要建置步驟或後端服務。

## 資料來源與載入備援
資料來源為台灣彩券今彩539歷史資料介面：`https://api.taiwanlottery.com/TLCAPIWeB/Lottery/Daily539Result?month=YYYY-MM&pageSize=500`。網站隨附 `assets/history-data.js` 內建200期歷史資料（截至115000269，來源CSV僅含期別及號碼，因此備援日期顯示「—」），頁面啟動時會先立即顯示最近15期，再於背景平行更新最近月份資料。瀏覽器快取30分鐘；按更新資料可強制重新抓取。即時介面若因網路、CORS或格式變更失敗，仍可使用快取或內建資料，不會無限停在讀取畫面；備援資料會明確標示來源與最新期別，不會假裝是即時資料。
