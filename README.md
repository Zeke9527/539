# 539 數據研究室 v6.1

純前端、無建置流程的 GitHub Pages 網站。部署後由瀏覽器向台灣彩券網站的今彩539資料介面抓取歷史開獎紀錄。

## 功能

- 自動逐月取得今彩539歷史開獎資料，可選最近 100／200／300／500 期。
- 預設自動帶入最新一期的五個號碼；也可自行輸入任意五個不重複號碼。
- 預測號碼數量可選 1～5 碼。
- **下一期轉移模型**：輸入一期的五個號碼，統計歷史上每個觸發號碼出現後，緊接著下一期的開獎分布。
- **六窗口模型**：最近 6、12、18、24、30、60 期標準化頻率偏差，含短窗口收縮。
- **綜合模型**：下一期轉移分數 70% + 六窗口分數 30%。
- **第五期序列模型**：選定一個起始期，讀取該期及其後四個開獎期的實際號碼，推算起始期之後的第五個開獎期。
- **後四期已開號碼排除法（新增）**：先以起始期五個號碼建立歷史「後五期至少出現一次」轉移排名，取前 8／10／12／15／20／39 名；再移除起始期之後第 1～4 期曾開出的候選號碼，保留原排名順序，作為第 5 期候選。
- 第五期模型預設使用最新可用起點：該起點後面四個開獎期均已開出，第五個開獎期尚未開出。
- 選擇較早的起始期時，會進入歷史回放模式：顯示第五個開獎期的實際結果和所選候選碼命中數。
- 第五期模型的訓練資料嚴格截止於所選起始期之前，避免將起始期之後的開獎結果洩漏到模型訓練中。
- 顯示五期輸入序列、訓練窗口數、候選排名及主要條件樣本。
- 排除法會同時顯示原始候選池、被移除號碼及其出現期別、最後保留號碼，以及歷史第五期實際命中情形。
- 可輸入自訂候選排名重現既有策略；自訂排名優先於模型排名，仍會顯示模型分數作為參考，但不會改動使用者提供的順序。
- 30 分鐘瀏覽器快取；資料抓取失敗時明確標示舊快取，不會冒充最新資料。
- 手機與桌面響應式排版。

## 模型定義

### 1. 下一期轉移模型

對輸入號碼 A，搜尋歷史上 A 出現的期別，統計其緊接著下一期號碼 B 的出現頻率：

```text
P(B in next draw | A in current draw)
```

採用單期隨機基準 `5/39 ≈ 12.82%` 作先驗平滑，先驗強度 10。五個觸發號碼各自計算後等權平均。

### 2. 第五期序列模型

使用者選定起始期 T0，系統讀取 T0、T1、T2、T3、T4 五個連續開獎期（T1～T4 是起始期後面已開出的四期），推算 T5（起始期之後第五個開獎期）。

歷史訓練樣本由五期輸入序列及緊接其後的目標期構成。對每個歷史五期序列，記錄在這五期中出現過的每個號碼 A，並統計下一期候選號碼 B 的出現率：

```text
P(B in T5 | A appeared in T0..T4)
```

選定的五期序列中，越接近預測日的四個後續開獎期給予越高權重（衰減係數 0.72）。各條件機率使用 `5/39` 先驗及強度 12 平滑後，加權平均排序。

對某個歷史起始期執行回放時，訓練資料只使用比起始期更早的歷史樣本；該起始期、後續四期與第五期實際結果都不會進入訓練集。歷史五期序列彼此可能重疊，不能把窗口數當成獨立樣本數。

### 3. 後四期已開號碼排除法

使用者選定起始期 D0。訓練資料只包含 D0 以前的歷史期數。先以 D0 的五個開獎號碼作為觸發條件，沿用歷史後五期轉移機率模型，取得39碼排序中的前 N 名候選（預設 N=12）。

接著讀取 D1～D4 四期的實際開獎號碼，將候選池中曾在 D1～D4 任一期出現過的號碼移除，其他候選保留原始排名順序，用於預測 D5。D0 本身不納入排除條件。若 D5 已開獎，頁面會顯示原始候選池與排除後候選的實際命中數。

這是一種「已觀察四期後，條件式縮小候選池」的方法，不是 D0 當下即可使用的五期預測；需要等 D1～D4 都開出後才能產生。排除某號碼只代表它已在觀察窗口出現，不代表它在 D5 的真實機率變成零；號碼可能連續開出，因此必須用逐期回測確認這種排除是否有幫助。

### 3. 六窗口模型

對最近 6、12、18、24、30、60 期分別計算標準化頻率偏差，並以收縮係數降低短窗口噪音。六個窗口高度重疊，不是六組獨立證據。

### 4. 綜合模型

先將下一期轉移分數與六窗口分數標準化，再以 70% 下一期轉移 + 30% 六窗口分數排序。此比例是目前的初始設定，不是經證明的最佳權重。

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新的 **Public** repository，例如 `539-data-lab`。
2. 將本資料夾內的所有檔案與資料夾上傳到 repository 根目錄，確認 `index.html` 位於根目錄。
3. 開啟 repository 的 **Settings → Pages**。
4. 在 **Build and deployment** 選擇 **Deploy from a branch**。
5. Branch 選 `main`、資料夾選 `/(root)`，按 Save。
6. 等待 GitHub Pages 完成部署，再開啟顯示的網站網址。

不需要 Node.js、套件安裝或編譯。修改後將更新檔案推送到 `main` 即可自動重新部署。

## 資料來源與限制

頁面使用的資料介面：

```text
https://api.taiwanlottery.com/TLCAPIWeB/Lottery/Daily539Result?month=YYYY-MM&pageSize=500
```

回應資料取自 `content.daily539Res`，使用欄位 `period`、`lotteryDate`、`drawNumberAppear`。

這是台灣彩券網站使用的資料介面，並非有公開版本承諾的正式開發者 API。若台彩變更介面、CORS 政策或回應格式，純靜態 GitHub Pages 可能無法直接取得資料；屆時需更新資料抓取程式，或另設 Cloudflare Worker 等後端代理。資料以台灣彩券官方公告為準。

```bash
node tests/model.test.cjs
```

測試涵蓋：候選池排序、只排除 D1～D4 出現過的號碼、D0 號碼不自動排除，以及 D5 結果不會洩漏至歷史排名。
