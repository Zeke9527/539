# 539 數據研究室｜最終版（TOP 15・排除後四期）

這是簡化後的單一策略版本，專為 GitHub Pages 設計。網站只保留最後定案的流程，不再包含下一期轉移、六窗口、綜合模型或第五期序列等其他模式。

## 唯一使用的模型

1. 自動從台灣彩券今彩539歷史資料介面取得最近100期開獎資料。
2. 畫面列出最近10期，每一期顯示期別、日期與5個號碼，使用者可選擇其中一組作為起始期 D0。
3. 只使用 D0 以前的歷史期數，分別統計 D0 五個號碼在歷史上出現後，接下來五期有哪些號碼至少出現一次。
4. 每個觸發號碼各自計算條件比例，使用等權重平均；以 `1 - (34/39)^5` 作為先驗機率，先驗強度為10。
5. 取綜合分數最高的前15碼，分數相同時以號碼小者優先。
6. 讀取 D0 之後的四期 D1～D4，將這四期曾出現過的候選號碼從前15碼中排除。D0 不排除，D5 也不會參與候選計分或排除。
7. 保留原始排名順序，依使用者選擇輸出1～5碼。若剩餘候選不足，顯示實際可輸出的數量，不會補入已排除號碼。

## 最近10期的選擇規則

最近10期全部顯示並可點選。若選定期別之後尚未累積完整4期開獎，頁面會顯示已累積幾期、尚缺幾期，並暫停產生結果。預設選中最近一個已具備後續4期資料的期別（通常是最新資料倒數第5期）。

若 D5 尚未開獎，頁面顯示預測模式。若 D5 已有結果，頁面改以歷史回放方式顯示原始候選池、排除後候選及實際命中數。

## GitHub Pages 部署

1. 在 GitHub 建立新的 Public repository，例如 `539-data-lab-final`。
2. 將本資料夾內所有檔案與 `assets`、`tests` 資料夾上傳到 repository 根目錄。
3. 確認 `index.html` 位於根目錄。
4. 進入 Settings → Pages → Build and deployment。
5. 選擇 Deploy from a branch，Branch 選 `main`，資料夾選 `/(root)`，儲存。
6. 等待 GitHub Pages 部署完成後開啟網站網址。

網站不需要 Node.js、建置步驟、資料庫或後端服務。Node.js 僅用於執行本機測試。

## 資料來源

頁面使用台灣彩券網站目前使用的今彩539資料介面：

```text
https://api.taiwanlottery.com/TLCAPIWeB/Lottery/Daily539Result?month=YYYY-MM&pageSize=500
```

資料取自回應 `content.daily539Res`，欄位包含 `period`、`lotteryDate`、`drawNumberAppear`。此介面不是具有公開版本承諾的開發者 API；若官方更改回應格式或 CORS 政策，GitHub Pages 直連可能失效。網站會清楚標示即時抓取失敗與快取狀態，不會把舊快取標示成最新資料。

資料每30分鐘快取於使用者瀏覽器。按「更新資料」可強制重新抓取。

## 本機測試

需要 Node.js 18 或更新版本：

```bash
node tests/model.test.cjs
```

測試會驗證：候選池固定15碼、只排除 D1～D4、D0 不自動排除、D5 不會洩漏到排名，以及未具備後續4期時不允許產生預測。

## 重要提醒

今彩539每期開獎為隨機事件。此工具僅將歷史資料依固定規則排序與排除，歷史條件關聯不代表未來機率會提高，也不保證命中。請勿把模型排名當成明牌或追號依據。開獎結果以台灣彩券官方公告為準。
