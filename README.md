# 539 數據研究室 v5

純前端、無建置流程的 GitHub Pages 網站。部署後由瀏覽器向台灣彩券網站的今彩539資料介面抓取歷史開獎紀錄，使用者輸入五個觸發號碼後，可產生 1～5 個候選號碼。

## 功能

- 自動逐月取得今彩539歷史開獎資料，預設最近 200 期，可選 100／200／300／500 期。
- 預設自動帶入最新一期的五個號碼；也可自行輸入任意五個不重複號碼。
- 產生 1～5 碼候選號碼。
- 三種模型：
  1. **後五期轉移模型**：對每個觸發號碼，搜尋歷史上該號碼出現後的五期，計算各候選號碼在這五期內至少出現一次的比例。
  2. **六窗口模型**：最近 6、12、18、24、30、60 期標準化頻率偏差，含短窗口收縮。
  3. **綜合模型**：轉移分數 70% + 六窗口分數 30%。
- 顯示每個觸發號碼的完整後五期樣本數、候選號碼排名與各觸發號碼的樣本命中數。
- 30 分鐘瀏覽器快取；資料抓取失敗時明確標示舊快取，不會冒充最新資料。
- 手機與桌面響應式排版。

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新的 **Public** repository，例如 `539-data-lab`。
2. 將本資料夾內的所有檔案與資料夾上傳到 repository 根目錄，確認 `index.html` 位於根目錄。
3. 開啟 repository 的 **Settings → Pages**。
4. 在 **Build and deployment** 選擇 **Deploy from a branch**。
5. Branch 選 `main`、資料夾選 `/(root)`，按 Save。
6. 等待 GitHub Pages 完成部署，再開啟顯示的網站網址。

不需要 Node.js、套件安裝或編譯。修改後將更新檔案推送到 `main` 即可自動重新部署。

## 資料來源與限制

頁面使用的資料介面：

```text
https://api.taiwanlottery.com/TLCAPIWeB/Lottery/Daily539Result?month=YYYY-MM&pageSize=500
```

回應資料取自 `content.daily539Res`，使用欄位 `period`、`lotteryDate`、`drawNumberAppear`。

這是台灣彩券網站使用的資料介面，並非有公開版本承諾的正式開發者 API。若台彩變更介面、CORS 政策或回應格式，純靜態 GitHub Pages 可能無法直接取得資料；屆時需更新資料抓取程式，或另設 Cloudflare Worker 等後端代理。資料以台灣彩券官方公告為準。

## 模型定義

在歷史資料由新到舊排列的前提下，對歷史上出現觸發號碼 A 的期數，找出其後五期（且五期均已開出），統計候選號碼 B 在這五期內至少出現一次的歷史比例。

任意指定號碼在獨立抽選假設下，未來五期至少出現一次的理論基準為：

```text
1 - (34 / 39)^5 ≈ 49.64%
```

為減少稀少樣本造成的極端估計，採用先驗強度 10 的平滑：

```text
(歷史後五期命中窗口數 + 10 × 49.64%) / (完整歷史樣本數 + 10)
```

每個輸入觸發號碼先各自計算，再以等權重平均。不同歷史觸發事件所對應的後五期窗口也可能彼此重疊，因此樣本窗口數不等於獨立樣本數。六窗口模型的視窗同樣彼此重疊，不能把六個窗口視為互相獨立的證據。所有模型只描述歷史資料，不能改變開獎的隨機性，也不保證提高中獎率。
